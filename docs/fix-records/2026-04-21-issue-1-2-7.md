## Issue #1：用结构化输出替换手动 JSON 解析

### 问题描述

当前每个 Agent（`RequirementAnalyzer`、`TestCaseGenerator`、`CaseReviewer`）都有大量手动解析 LLM 输出的代码：
- `_extract_json()` — 从 markdown 代码块中提取 JSON
- `_fix_json_format()` — 修复格式问题
- `_fallback_parse()` — 降级解析方案

这些代码脆弱、重复，且难以维护。

### 修复方案

使用 LangChain 的 `with_structured_output` 直接绑定 Pydantic 模型，让框架处理解析：

```python
# 修复前（脆弱）
content = self.llm.chat_simple(prompt)
json_data = self._extract_json(content)   # 各种修复逻辑
result = self._parse_llm_response(json_data)

# 修复后（稳定）
structured_llm = self.llm.with_structured_output(RequirementAnalysisResult)
result = structured_llm.invoke(prompt)   # 直接返回 Pydantic 对象
```

### 修改文件

| 文件 | 修改内容 |
|------|----------|
| `core/utils/llm_client.py` | 添加 `with_structured_output()` 方法 |
| `core/agents/requirement_analyzer.py` | 使用结构化输出，保留降级方案 |
| `core/agents/test_case_generator.py` | 使用结构化输出，保留降级方案 |
| `core/agents/case_reviewer.py` | 使用结构化输出，保留降级方案 |

### 预期收益

- 消除约 150 行重复的 JSON 解析代码
- 解析失败率大幅降低
- 代码可读性显著提升

## Issue #2：评审反馈注入生成器（有效迭代）

### 问题描述

当前评审不通过后的迭代是"盲目重试"——`generate_test_cases_node` 重新执行时完全不知道上一次哪里出了问题，导致迭代没有实际改进效果。

### 修复方案

将评审意见作为约束条件注入生成器的 prompt：

```python
# workflow.py
def generate_test_cases_node(state: AgentState) -> dict:
    iteration = state.get("iteration_count", 0)
    review_suggestions = state.get("review_suggestions", [])

    # 第二次及以后迭代，带上上次的问题
    improvement_hints = None
    if iteration > 0 and review_suggestions:
        MAX_HINTS = 5
        improvement_hints = review_suggestions[:MAX_HINTS]

    for req in requirements:
        test_cases = generator.generate(req, improvement_hints=improvement_hints)
```

```python
# test_case_generator.py
def _build_prompt(self, requirement: Requirement, improvement_hints: Optional[List[str]] = None) -> str:
    hints_section = ""
    if improvement_hints:
        hints_list = "\n".join(f"  - {hint}" for hint in improvement_hints)
        hints_section = f"""
## ⚠️ 上次评审发现的问题（本次必须修复）

{hints_list}

**重要**: 本次生成必须解决上述问题，否则评审将再次不通过。
"""
```

### 修改文件

| 文件 | 修改内容 |
|------|----------|
| `core/agents/test_case_generator.py` | 添加 `improvement_hints` 参数，修改 `_build_prompt()` |
| `core/agents/workflow.py` | 在 `generate_test_cases_node` 中注入改进提示 |

### 验证结果

对比实验显示：
- 第一次生成：5 个用例，得分 87.0，6 条改进建议
- 第二次生成：15 个用例，得分 88.0，0 条改进建议
- 改进建议全部被采纳，新增边界测试、安全测试等高质量用例

## Issue #7：LLMClient 重试机制和 Token 成本追踪

### 问题描述

当前 `LLMClient.chat()` 直接调用 `self._llm.invoke()`，没有任何容错处理：
- 网络抖动或 API 限流时直接抛出异常，整个工作流中断
- 没有记录每次调用的 Token 消耗，无法统计成本
- 每次调用都创建新的 `LLMClient` 实例，浪费资源

### 修复方案

**1. 加入指数退避重试：**

```python
from tenacity import retry, stop_after_attempt, wait_exponential, retry_if_exception_type

@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=2, max=10),
    retry=retry_if_exception_type((httpx.TimeoutException, httpx.ConnectError))
)
def chat(self, messages, ...):
    ...
```

**2. Token 成本追踪：**

```python
class TokenTracker:
    """全局 Token 使用统计"""
    _instance = None
    _lock = threading.Lock()

    def record(self, usage: TokenUsage):
        self.total_prompt_tokens += usage.prompt_tokens
        self.total_completion_tokens += usage.completion_tokens

    def get_summary(self) -> Dict[str, Any]:
        return {
            "call_count": self.call_count,
            "total_prompt_tokens": self.total_prompt_tokens,
            "total_completion_tokens": self.total_completion_tokens,
            "total_tokens": self.total_tokens,
        }
```

**3. 单例 LLMClient：**

```python
_client_instance = None
_client_lock = threading.Lock()

def get_llm_client() -> LLMClient:
    global _client_instance
    if _client_instance is None:
        with _client_lock:
            if _client_instance is None:
                _client_instance = LLMClient()
    return _client_instance
```

## 额外修复：max_tokens 限制导致 JSON 解析失败

### 问题描述

第二次生成时，注入改进提示导致 LLM 输出过长，超过 `max_tokens` 限制，JSON 被截断导致解析失败。

### 修复方案

1. 增加 `max_tokens`：4096 → 8192
2. 限制改进建议数量：最多注入 5 条

### 修改文件

| 文件 | 修改内容 |
|------|----------|
| `core/models/config.py` | `llm_max_tokens`: 4096 → 8192 |
| `core/agents/workflow.py` | 限制改进建议数量为 5 条 |
