## Issue #14：Requirement ID 格式限制过严，超过 999 个需求就崩溃

### 问题描述

`Requirement` 和 `TestCase` 的 ID 格式用正则强制限制为 3 位数字：

```python
# 修复前（限制过严）
# core/models/requirement.py
id: str = Field(pattern=r"^REQ_\d{3}$")  # 只允许 REQ_001 ~ REQ_999

# core/models/test_case.py
id: str = Field(pattern=r"^TC_\d{3}$")   # 只允许 TC_001 ~ TC_999
```

当需求超过 999 个，或者 LLM 生成了 `REQ_0001`（4位）、`TC_001_001`（子用例）这样的 ID 时，Pydantic 验证直接失败，触发降级逻辑。

### 影响链路分析

**受影响的执行链路：**
1. **需求分析链路** — LLM 生成的 ID 超过 3 位数字时验证失败，触发降级解析
2. **测试用例生成链路** — 生成的 TC_001_001 等子用例格式被拒绝
3. **端到端测试链路** — 验证失败导致整个工作流中断

**影响范围：** 全局（影响所有 ID 验证）

### 修复方案

放宽正则，支持更多位数和子用例格式：

```python
# 修复后（放宽限制）
# core/models/requirement.py
id: str = Field(pattern=r"^REQ_\d{1,6}$")  # 支持 REQ_1 ~ REQ_123456

# core/models/test_case.py
id: str = Field(pattern=r"^TC_[\d_]+$")   # 支持 TC_001、TC_0001、TC_001_001
```

### 修改文件

| 文件 | 修改内容 |
|------|----------|
| `core/models/requirement.py` | ID 正则从 `\d{3}` 改为 `\d{1,6}` |
| `core/models/test_case.py` | ID 正则从 `\d{3}` 改为 `[\d_]+` |
| `tests/unit/test_requirement_model.py` | 新增 5 个 Requirement ID 格式测试 |
| `tests/unit/test_test_case_model.py` | 更新 TestCase ID 格式测试 |

### 涉及方法说明

| 方法名 | 所在文件 | 作用说明 |
|--------|----------|----------|
| `Requirement.id` 字段 | `requirement.py` | 需求唯一标识符，用于关联测试用例 |
| `TestCase.id` 字段 | `test_case.py` | 测试用例唯一标识符，用于生成测试文件名 |
| `field_validator` | Pydantic | Pydantic V2 字段验证器，用于自定义验证规则 |

**示例：**
```python
# 修复前：这些 ID 会验证失败
Requirement(id="REQ_0001", ...)  # 4位数字，失败
TestCase(id="TC_001_001", ...)   # 子用例格式，失败

# 修复后：这些 ID 都能通过验证
Requirement(id="REQ_1", ...)     # 1位数字，通过
Requirement(id="REQ_123456", ...)  # 6位数字，通过
TestCase(id="TC_001_001", ...)   # 子用例格式，通过
```
