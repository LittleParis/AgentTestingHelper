# Issue #22：AllureReporter.open_report 进程泄漏修复

## 问题描述

`open_report()` 用 `subprocess.Popen` 启动 HTTP 服务进程，存在进程泄漏问题：

```python
# 原来的问题代码
process = subprocess.Popen(
    [sys.executable, "-m", "http.server", ...],
    creationflags=DETACHED_PROCESS,  # 进程脱离父进程
    close_fds=True,
)
return {"pid": process.pid, ...}  # 返回 PID 但没有清理机制
```

问题：
- 进程 PID 返回后无法被清理
- Windows 上 `DETACHED_PROCESS` 让进程完全脱离父进程
- 每次运行都启动新进程，端口随机，旧进程一直占用内存
- 无法被 Python 的 `atexit` 清理

## 影响链路分析

- **文件**: `core/automation/allure_reporter.py`
- **影响范围**: 打开 Allure 报告的功能
- **影响链路**: 生成报告 → 打开报告 → 进程泄漏 → 内存占用

## 修复内容

采用方案 C（最简单）：直接用 `webbrowser` 打开静态 HTML 文件：

```python
import webbrowser

def open_report(self) -> dict:
    """打开已生成的 Allure 报告"""
    if not self.report_dir.exists():
        return {"status": "error", "error": f"报告目录不存在: {self.report_dir}"}

    index_file = self.report_dir / "index.html"
    if not index_file.exists():
        return {"status": "error", "error": f"报告文件不存在: {index_file}"}

    # 使用 webbrowser 直接打开静态 HTML 文件
    url = f"file:///{index_file.absolute().as_posix()}"
    webbrowser.open(url)

    return {
        "status": "success",
        "message": f"已在浏览器中打开报告: {url}",
        "url": url,
    }
```

## 涉及方法说明

| 方法 | 说明 |
|------|------|
| `webbrowser.open()` | 系统默认浏览器打开 URL，由操作系统管理进程 |
| `Path.as_posix()` | 将 Windows 路径转换为 POSIX 格式（用于 file:// URL） |
